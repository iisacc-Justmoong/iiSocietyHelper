# 관리 파일 저장·검색

`Dreamscapes/GenerationInputs`의 관리 대상 디렉터리를 제거하는 Helper API도
일반 파일과 같은 휴지통 경로를 사용한다. 최종 삭제 전에는 디렉터리와 그
안의 파일 및 메타데이터를 복구할 수 있어야 한다.

## 경로 메타데이터 전환 계약

`FileSystem`의 명시적 저장과 가져오기는 새 파일의 디렉터리 메타데이터만 기록하며
원본이나 판본을 객체 저장소에 복제하지 않는다. `removeFile()`은 일반 섹션의
항목을 휴지통으로 옮기고 `deleted` 섹션에서만 최종 삭제한다. 분류 변경은 해당
파일 옆 문서의 기대 판본을 검증해 갱신한다. 새 저장 방식과 레거시 이력이 충돌하면
확인되지 않은 소유권을 자동으로 전환하지 않는다.

`FileSystem`의 새 파일 저장·가져오기와 캔버스·미디어 발행은 파일 옆의
메타데이터를 사용한다. 기존 디렉터리 소유 파일의 명시적 원자 교체는 사전에 읽은
문서와 교체 직후의 파일 상태를 대조하여 같은 파일 ID를 유지하고 오래된 해시는
지운다. 레거시 파일의 명시적 교체는 기존 분류와 파일 상태를 검증하고 동일한
분류 키에 새 파일 상태를 연결한다. 기존 객체 이력은 수정하거나 새 본문으로
복제하지 않는다. 저장·이동과 SQLite 및 메타데이터 문서는 하나의 파일시스템
트랜잭션이 아니므로 중간에 프로세스가 중단되면 확인과 조정이 필요할 수 있다.

설치 패키지는 `iiSocietyHelper_HAS_MANAGED_FILES` 기능 변수를 제공한다. 동일 버전의 예전 패키지와 혼합하지 않도록 앱이 이 변수를 확인한다.

Apple 파일 선택기의 NFC/NFD 표기 차이는 네이티브 경로 검증과 실제 파일 철자로 정리한다. 분해형 한글 이름으로 저장한 파일을 같은 인자로 다시 편집해도 동일한 관리 경로를 사용한다. 다른 플랫폼의 서로 다른 파일 이름은 합치지 않는다.

`requestSynchronization()`과 `indexFiles()`는 기존 레거시 기록을 재조정하되
새 파일 본문을 수집하지 않는다. 새 파일의 자동 SHA-256 관찰은 Society 데몬이
제한된 작업량으로 수행한다. 취소 시 공개 파일과 기존 이력은 보존한다.

호스트의 외부 수집은 마지막 파일 이벤트 이후 2초 동안 잠잠해지고 현재 인덱싱·전송이 끝난 뒤 낮은 우선순위 작업자에서 시작한다. 전송 중에는 다시 예약하며, 앱의 직접 저장·발행 기록은 이 지연을 사용하지 않는다. 내부 분류 DB·WAL·프리뷰는 파일 감시와 복제 색인에서 제외하여 자기 갱신이 다시 수집을 유발하지 않도록 한다. 사용자 분류 동반 문서는 기존 복제 계약을 유지한다.

서버 내부 상태의 `.iiwebserver-*` 접두사도 파일 감시와 복제 색인에서 제외한다. `Sync.WatchPaths`는 이 디렉터리와 Provider 상태를 제외하면서 사용자 숨김 파일과 분류 문서를 유지하는 계약을 검증한다.

추가 API는 다음과 같다.

- `searchFiles(request)`: 제목·키워드·등급·색상·컬렉션 또는 온톨로지 클래스·타입 조건·가상 폴더를 Provider 인덱스로 검색한다. 결과의 `path`는 논리 경로이다.
- `setFileMetadata(section, relativePath, metadata)`: 제목·설명·키워드·등급·색상·사용자 필드·컬렉션을 해당 파일의 디렉터리 문서에서 교체한다. 이전 객체는 검증된 기존 경로를 사용한다.
- `fileJournal(afterSequence, limit, objectKey)`: 지속 sequence를 기준으로 바이트·메타데이터·이동·삭제 이벤트를 가져온다. RAW 메타데이터 이벤트는 RAW 키에 속한다.
- `workSessions(afterSequence, limit)`: 앱 이름·버전·프로젝트·문서와 세션 시작/종료 정보를 조회한다.
- C++ `applyOntology(changes, expectedRevision)`: Provider의 명시적 클래스·관계·가상 폴더 편집을 동일 세션과 CAS 계약으로 수행한다.

위 API는 블로킹 I/O이다. UI는 I/O 소유자 또는 기존 비동기 앱 어댑터를 사용한다. `fileInformation().managed`는 새 파일의 메타데이터 ID와 현재 해시 상태 또는 기존 객체의 RAW·세션 정보를 반환한다. 조회는 관리 DB를 새로 만들지 않는다.

로그인 사용자나 원작자 인증은 추정하지 않는다. 과거에 보관된 이력은 보존하며
새 디렉터리 메타데이터 등록은 보관된 원본이나 이전 판본의 존재를 뜻하지 않는다.

실제 저장·검색 계약과 오류 복구 규칙은 iiSocietyContainer의 `docs/ManagedFiles.md`를 따른다. `tests/managed_storage.cpp`는 실제 저장·원자 교체·분류 검색·휴지통·최종 삭제와 레거시 이력 보존을 검증한다.

파일 시스템 전체 회귀 검사는 여러 저장소의 내구 쓰기와 종료 시 수집 작업 취소·정리까지 포함하여 프로세스 제한을 300초로 둔다. 개별 GUI 요청 100 ms 및 저장소 전환 10초 검증은 유지한다. 동기화 컨트롤러 역시 파일 이벤트 반영 1.8초·5초 검증과 별도의 지연 수집 완료 검증을 함께 수행한다.
