# 동기화 저널의 초기 준비

새 저널의 기본 테이블·분리 복구 테이블·네임스페이스 테이블과 schema version 3은
한 SQLite 트랜잭션으로 초기화한다. 개별 DDL마다 내구성 동기화를 반복하지 않는다.
WAL과 `synchronous=FULL`은 유지하며 커밋 이전 실패 시 전체 생성 작업을 롤백한다.
기존 저널의 호스트·계정 바인딩, 복구 절차와 schema 3 데이터 이관도 유지한다.

오래된 저널의 기반 DDL 업그레이드와 네임스페이스 초기화도 같은 트랜잭션에 묶는다.
이미 완성된 schema 3 저널은 불필요한 영속 변경을 만들지 않는다.
`failedNamespaceMigrationRollsBackTheWholeNewJournal`은 손상된 기존 네임스페이스를
만났을 때 schema 번호나 부분 기본 테이블이 남지 않는지 확인한다.

기존 `SOCIETY_SYNC_TRACE=1`을 켜면 공유 저장소 열기·저널 열기·감시 경로 준비의
소요 시간을 분리해서 기록한다. 계정 토큰이나 파일 내용은 이 측정에 포함하지 않는다.

같은 메타데이터 값과 이미 반영된 peer cursor는 다시 쓰지 않는다. 네트워크에서 이전 cursor가 재전달되어도 최대 진행 위치는 유지하며, 불필요한 FULL 동기화와 카탈로그 무효화를 방지한다. `unchangedPeerCursorsDoNotCreateAnotherDurableRevision`은 별도 SQLite 연결의 data_version이 그대로 유지되고 실제 cursor 증가 때만 바뀌는지 검사한다.

## 일시적인 잠금 충돌

`sync_store_busy`는 Replica가 작업을 시작하기 전에 반환하는 잠금 충돌이다. Controller는 같은 요청 토큰을 pending 상태로 유지하고 1~50밀리초 간격으로 재시도한다. 기존 120초 요청 기한을 연장하지 않으며 세대 변경·취소 시 재시도를 중단한다. 이미 수행한 작업은 재실행하지 않는다. Controller 회귀 검사는 잠금 해제 전 pending 유지와 해제 후 동일 요청의 완료를 확인한다.

## WAL 읽기와 파일 변경 잠금

변경 목록과 네임스페이스 저널 조회는 SQLite SAVEPOINT로 고정한 WAL 읽기 스냅샷을 사용한다. 디스크의 operation.lock 파일을 매번 생성·동기화할 이유가 없으므로 읽기에 파일 변경 잠금을 사용하지 않는다. 한 페이지의 cursor·항목·네임스페이스는 같은 커밋 상태에서 읽는다. 다른 연결의 미커밋 쓰기는 보이지 않는다.

변경 없는 카탈로그 게시와 이미 반영된 cursor도 잠금을 새로 만들기 전에 확인한다. 실제 카탈로그 변경·cursor 저장·파일 쓰기는 기존 잠금과 재검증을 사용한다. SQLite WAL 및 synchronous=FULL, 실제 파일 쓰기의 내구성은 그대로이다. metadataPagesReadACommittedWalSnapshotWhileTheOperationLockIsHeld 회귀 검사는 외부 변경 잠금과 미커밋 DB 쓰기가 있는 동안 마지막 커밋만 조회하고 기존 잠금 파일을 보존하는지 확인한다.


동기화 삭제에서 빈 디렉터리에 남은 `.iisacc-temporary.lock`은 사용자 콘텐츠로 판정하지 않는다. 실제 제거는 기존 ConfinedFiles 경로를 사용하여 빈 일반 파일·단일 링크·배타 잠금을 검증하고 안정된 잠금 inode를 보존한 채 디렉터리를 분리한다. 다른 사용자 파일이나 활성 작성자는 계속 삭제를 막는다. Synchronizer 회귀 검사는 유휴 잠금 파일이 있는 디렉터리 삭제를 검사한다.

변경 없는 파일 순회와 이미 삭제된 항목의 재확인, 빈 네임스페이스 페이지 확인은 읽기 경로로 처리한다. 변경이 있을 때만 작업 잠금을 취득하고 파일 상태를 다시 검사한 뒤 기존 FULL 동기화 트랜잭션을 수행한다. 빈 페이지도 기존 권한·해시·커서 검증을 그대로 거친다. 회귀 검사는 외부 작업 잠금이 유지된 상태의 무변경 순회와 빈 페이지 확인, 잘못된 권한 거부를 검증한다.

64 KiB 이하 파일은 상대의 `describe.inlineBytes` 지원 선언이 있을 때 `commit.inlineData`에 담아 단일 커밋한다. Base64 형식·정확한 크기·SHA-256·여유 공간을 검증한 뒤 기존 임시 전송·충돌 병합·내구성 경로로 커밋하고 응답한다. 상대가 이 기능을 알리지 않으면 기존 begin/chunk/commit 경로를 사용하며 대용량 청크 재개 방식은 유지한다. 회귀 검사는 협상·기존 상대와의 호환·손상 거부·기존 파일 보존을 검사한다.

반복 핸드셰이크의 mirror.json 내용이 이미 동일하면 기존 파일과 수정 시각을 보존한다. 바인딩 파일이 없거나 내용이 달라졌을 때만 기존 원자적 저장을 수행한다. 잠금·호스트 검증·복구 절차는 유지하며, 회귀 검사는 반복 바인딩의 무쓰기 동작과 사라진 바인딩 파일의 복구를 검사한다.

단일 요청 전송도 기존 commit 확인 단계로 전달하므로, 확인 도중 발생한 로컬 변경과 응답 유실 시의 재처리 검사를 그대로 적용한다.
